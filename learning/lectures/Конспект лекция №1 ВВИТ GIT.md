## Notes in my words

Система контроля версий Git — программное обеспечение, хранящие историю изменений файлов и позволяющее управлять разными версиями проекта. (Слайд 6.) Git позволяет сравнивать версии файлов и совмещать работу над одним проектом нескольким людям без доступа в интернет. 

С помощью сервиса GitHub можно организовать совместную работу над проектом, добавлять различные задачи и обсуждения.  На этом сайте можно свободно размещать репозитории. 

Репозиторий — хранилище проекта, в котором находятся все файлы и служебный каталог .git . Для того чтобы создать репозиторий, нужно ввести в командную строку команду `git init`. В служебной папке лежат все версии файлов, ветки, теги, указатель HEAD и настройки конфигурации. 

Для указывания данных о пользователе используются команды `git config --global user.name "ФИО"` и `git config --global "почта"`. 

Для того, чтобы отобрать изменения используется команда `git add название файла`, а для создания коммита — `git commit название коммита`. Команда `git add .` позволяет добавить все изменения текущего каталога, а `git add "название папки"/` — все содержимое папки.

Коммит — зафиксированная точка в истории проекта. В него попадает только то, что было отобрано в индекс. Каждый коммит знает автора, время, сообщение и предыдущий коммит. (Слайд 16)

Для того чтобы увидеть всю историю проекта, используется команда `git log`. В ней видны каждые коммиты с подписью автора, дата внесенного изменения и хэш — уникальный идентификатор, вычисляющийся из содержимого коммита.

Команда `git diff` сравнивает только что отредактированные файлы. Она показывает то, что было изменено, но еще не было добавлено в индекс. Команда `git diff --staged` сравнивает индекс с последним коммитом, то, что уже отобрано и войдет в коммит. 

Ветки позволяют проводить различные эксперименты без ущерба основной части проекта. Команда `git branch` показывает список всех веток. Для создания новой используется команда `git branch "название ветки"`, а для того чтобы перейти в нее — `git switch 'название ветки'`. Чтобы создать ветку и сразу перейти в нее используется команда `git switch -c "название ветки"`. После проверки изменений нужно объединить новую ветку с основной, для этого переходим на основную ветку и используем команду `git merge`. Если одни и те же строки файла изменены по разному в двух ветках, возникает конфликт слияния. Чтобы продолжить редактировать проект нужно либо выбрать нужные изменения, либо объединить их.

Для отмены изменения используется несколько команд. В случае если изменения только в рабочем каталоге, нужна команда `git restore "название файла"`. Файл вернется к состоянию из последнего коммита, а все несохраненные правки будут удалены. Если изменения уже в индексе, пишем команду `git restore --staged "название файла"` . Изменение уйдет из индекса, но останется в рабочем файле. Если изменение уже закоммичено используется команда `git revert "хэш коммита"` . В этом случае Git создаст новый коммит, отменяющий указанный. (слайд 30). Команда `git reset --hard HEAD~1` позволяет переместить указатель ветки на другой коммит, незакоммиченные изменения при --hard исчезают.

С помощью удаленного репозитория вся команда разработки имеет доступ ко всей истории проекта, каждый участник синхронизирует с ней свою локальную версию. Команда `git clone "ссылка на репозиторий"` скачивает текущие файлы проекта и всю его историю. Используя `git remove -v` можно узнать с какими удаленными репозиториями связан проект, на выходе мы получаем origin (имя удаленного репозитория), url (ссылка на репозиторий), fetch (откуда забираются изменения) и push (куда отправляются  коммиты). Команда `git fetch` скачивает все новые коммиты и обновляет ссылки вида origin/main. Команда `git pull` скачивает изменения и сразу интегрирует их в текущую ветку. С помощью команды `git push` можно отправить свои коммиты в удаленный репозиторий. В случае, если существуют файлы, которые не должны попасть в удаленный репозиторий, закидываем их в папку .gitignore. 


## Key ideas

Репозиторий — хранилище проекта, в котором хранятся все изменения файла с автором этих изменений и коммитами (заметками о них). Для создания репозитория используем `git init`, для коммита `git commit -m`. Если нужно перейти на другую ветку, пишем `git switch "название ветки"`, а если нужно отменить правки, то `git restore "название файла"` (отменяет правки), `git restore --staged "название файла"` (убирает из индекса), `git revert "хэш коммита"` (отменяет коммит). Если файл не должен быть на GitHub - закидываем его в .gitignore

Репозиторий — хранилище проекта, где находятся файлы, история изменений и коммиты к ним. Коммит фиксирует изменения в индексе.
